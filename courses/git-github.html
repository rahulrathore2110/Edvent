EDVENT — Complete Git and GitHub Master Syllabus

Beginner to Advanced | Structured Learning Path

This syllabus is designed for students learning web development, backend development, data analytics, and professional software engineering. It progresses from version-control fundamentals to advanced Git workflows, collaborative GitHub development, code reviews, automation, release management, and portfolio projects.

The objective is for students to confidently manage real projects, collaborate with teams, resolve conflicts, recover from mistakes, and maintain professional GitHub repositories.

1. Course overview

Git — Version control system

Track changes, create branches, merge work, inspect history, recover files, and manage code across different versions.

GitHub — Collaborative development platform

Host Git repositories, collaborate through pull requests, review code, manage issues, automate workflows, and publish project documentation.

Course detail Recommendation
Target audience Complete beginners through intermediate developers
Prerequisites Basic computer usage and file management
Programming prerequisite None for Git fundamentals
Recommended duration 8–10 weeks
Practice time 5–8 hours per week
Tools Git, GitHub, terminal, VS Code
Primary outcome Independent Git user and confident GitHub collaborator
Final project Professional repository with branches, pull requests, releases, and automated checks

Important distinction: Git and GitHub are not the same. Git is the version-control system; GitHub is a platform that hosts Git repositories and adds collaboration, project-management, security, and automation features.

16.3 Reset versus revert

Operation Main purpose Effect on history
git reset --soft Move branch pointer while keeping changes staged Rewrites local branch history
git reset --mixed Move branch pointer and leave changes unstaged Rewrites local branch history
git reset --hard Move branch pointer and discard tracked working-tree changes Rewrites local branch history; potentially destructive
git revert Create a new commit that reverses an earlier commit Preserves existing history

Teach students to prefer git revert when undoing changes already shared with a team, unless the team has explicitly agreed on a different history-rewriting procedure.

25.4 First CI workflow

Example: a basic Node.js workflow that installs dependencies and runs the project's test script.

name: Node.js CI

branches: [main]

test:

- name: Checkout repository

- name: Set up Node.js

uses: actions/setup-node@v4

node-version: 22

cache: npm

- name: Install dependencies

run: npm ci

- name: Run tests

This is an instructional example. For production course material, use current supported action versions and the Node.js version selected for the project. The workflow also assumes that the repository has a valid lockfile and a working test script.

Recommended 10-week learning roadmap

For EDVENT, use this sequence so that students master the fundamentals before moving into advanced commands and GitHub automation.

Week 1

Version control and setup

Version-control concepts, terminal basics, installation, Git configuration, repository initialization.

Deliverable: Create the first local repository.

Week 2

Staging and commits

Working tree, staging, commits, diffs, history, `.gitignore`, commit messages.

Deliverable: Build a project with meaningful commit history.

Week 3

Branches and merges

Branch creation, switching, merging, fast-forward and three-way merges, conflict resolution.

Deliverable: Complete a branching and conflict lab.

Week 4

GitHub fundamentals

Account security, repositories, remotes, clone, push, pull, fetch, README and Markdown.

Deliverable: Publish a documented project.

Week 5

Collaboration

Forks, upstream, pull requests, reviews, Issues, Projects, GitHub Flow.

Deliverable: Complete a collaborative pull request.

Week 6

Recovery and advanced Git

Restore, reset, revert, stash, reflog, cherry-pick, rebase, tags.

Deliverable: Recover from deliberately introduced mistakes.

Week 7

Professional workflow

Branching strategies, releases, changelogs, repository standards, code review.

Deliverable: Prepare a versioned release.

Week 8

GitHub Actions

YAML, workflows, runners, CI, automated tests, secrets and workflow permissions.

Deliverable: Automate checks on pull requests.

Week 9

Security and advanced GitHub

Branch protection, rulesets, dependency security, open-source contribution, organization permissions.

Deliverable: Harden a practice repository.

Week 10

Portfolio and final assessment

End-to-end collaborative workflow, documentation, release, testing, presentation.

Deliverable: Submit the final GitHub portfolio.

Daily practice routine

For a 60–90 minute session:

15 minutes: Review previously learned commands.

20 minutes: Learn one new concept.

30–40 minutes: Perform hands-on exercises.

10 minutes: Explain what happened and document mistakes.

Do not make students memorize every command. Make them predict what a command will do, inspect the repository state, execute it, and verify the result.

Final recommendation

For EDVENT's students, make Git fundamentals and collaborative GitHub workflows compulsory before students begin serious React, Node.js, or data analytics projects. Teach advanced Git internals, interactive rebase, submodules, and complex CI/CD only after students can confidently create branches, commit changes, resolve conflicts, open pull requests, and recover from mistakes.

The course is successful when students can independently contribute to a shared repository and explain exactly how their changes move from a local working directory to a reviewed, tested, and released project.
